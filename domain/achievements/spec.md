# Achievements (ACH)

## 1. Purpose and scope

This context decides which achievements exist, what each one asks of the player, when its test runs,
which campaigns may earn achievements, how progress and unlocks reach the three stores (Steam, Game Center,
Google Play Games), how achievements look (icons, toast, screen), and how the list may grow later.

**In scope**
- The achievement list (71 at launch), its tiers and points, categories, scope (campaign / lifetime),
  hidden flag, `full_game` flag, test moment (`moment`), test and progress counter.
- The store limits adopted, store ids, the build step that writes store upload files, retiring achievements.
- Eligibility: ironman-only, cheat marking, switching country after game over, tutorial, demo.
- Running tests at the end of a turn or at named moments.
- Progress reporting to each store; the offline unlock queue and catch-up on start-up.
- Free mobile tier and Steam demo carry-over rules for achievements.
- Icons; the unlock toast; the achievements screen's content and filter; the turn report line.
- Reserve slots and points for updates.

**Not in scope (owned by …)**
- The ironman mode itself, the save header flags, the player profile and its cloud sync, demo-to-full save
  carry-over (saves).
- Where the achievements screen sits, the game-over "play on as another realm" button and its wording, the
  pause menu (game-shell).
- The "Achievement toasts" switch (settings).
- The unlock sound `ui_achievement` (audio).
- The stats and moments each test reads (realm, province, research, warfare, naval, exploration, diplomacy,
  subjects, rebellions, events, recruiting, trade, scenario-setup, time-and-turns).
- How a campaign is won and its scores (gap list 1, item 1; not designed yet).
- The free tier's countries are the Ottomans and France (game-shell `freeRealms`); the rows they cannot earn are marked `full_game` (D-ACH-3).

## 3. Ubiquitous language

| Term | Meaning | Not to be confused with |
|---|---|---|
| Achievement | One row of `achievements.yaml`: a goal with a name, text, tier, test and moment. Gives nothing inside the game | A campaign victory or score (gap list 1, item 1) |
| `id` | Our own stable snake_case name of an achievement. Never renamed after release; store ids are derived from it | The Google Play id (generated by its console) |
| Name | Shown name, at most 24 characters | Text |
| Text | What to do, at most 100 characters, written as an instruction | Test |
| Category | One of: first_steps, realm, lords, learning, war, sea, order, abroad, history, campaign | Tier |
| Tier | Copper (5 points), Silver (10), Gold (20), Crown (40) | Category |
| Points | The store score of an achievement, set by its tier; shown by Game Center and Google Play, not Steam | Gold in the treasury |
| Scope | `campaign`: the whole condition is met inside one game. `lifetime`: counts across games, kept in the player profile | Campaign rules |
| Moment (`moment`) | The game moment whose occurrence runs an achievement's test | A turn phase of another context |
| Test | The condition, written in the event tree's trigger style | Moment |
| Progress row | A row with `progress: {stat, target}`: a game counter reported to stores as a progress bar | The test itself |
| Hidden achievement | `hidden: true`: name and text secret until earned; shown as "Hidden achievement" with its tier | A locked (not yet earned) achievement |
| `full_game` | The achievement can't be earned with the free mobile tier's countries alone | Steam demo |
| Ironman campaign | A campaign started as ironman (saves context). The only kind that earns achievements | Normal campaign |
| Cheat-marked save | A save on which a debug, editor or "free play" cheat was used even once. Marked for good | A save that fails the hash check (saves) |
| Switched country | Playing on as another country after game over | Changing the start nation in setup |
| Eligible campaign | A campaign where `ironman_unbroken` is true, `cheat_marked` is false and `switched_country` is false | |
| Lifetime counter | A counter kept in the player profile across games (`paths_not_taken`, `many_crowns`, `every_macro_region`) | A campaign counter |
| Campaign counter | A progress counter that resets with each new game | Lifetime counter |
| Best reported value | The highest progress value already sent to a store for a progress row | This campaign's own value |
| Unlock queue | The small offline queue that sends unlocks to the store when reachable | Save upload queue (saves) |
| Toast | The banner that slides in at the top for three seconds when an achievement unlocks | Turn report line |
| Reserve | The slots (29) and points (320) kept for updates | |
| Retired achievement | An achievement hidden in every store with its test turned off; never deleted | |
| `event_role` | The event tree's role in a historical event, so whoever holds the role can earn the achievement | A named country |

## 4. Domain model

### Aggregates

**AchievementCatalogue** (identity: the config file version)
- Holds: tiers `{copper: 5, silver: 10, gold: 20, crown: 40}`; the list of AchievementDefinitions; the reserve.
- INV-ACH-1: at most 100 achievements, ever (counting retired ones, since they are never deleted).
- INV-ACH-2: every achievement's points are a multiple of 5 and at most 40; the sum of all points is at most 1,000.
- INV-ACH-3: every `id` is unique and stable; an `id` is never renamed after release.
- INV-ACH-4: every name is at most 24 characters and every text at most 100 characters.
- INV-ACH-5: no test names a country; only `japan_whole_1600` and `sahel_whole_1600` name a region.
- INV-ACH-6: no test is tied to an event marked `narrative_only`, to conquering a named people, or to sacking or scorching land.
- INV-ACH-7: every `moment` value is one of the moments in §4 "Moments", `castle_gained` included (D-ACH-1).
- INV-ACH-8: after each update at least 10 slots and 100 points stay in reserve.
- INV-ACH-9: no achievement grants anything inside the game (no bonus, no unlocked nation, no cosmetic).

**PlayerAchievementProfile** (identity: the player profile; stored and synced by saves)
- Holds: unlocked achievements with date earned; lifetime counters; best reported value per progress row and
  store; the unlock queue; the demo's local list (Steam demo only).
- INV-ACH-10: an unlock is written to the profile before it is sent to any store.
- INV-ACH-11: lifetime counters only count campaigns that are eligible.
- INV-ACH-12: a store's reported progress never goes down.

**CampaignAchievementState** (identity: the campaign; carried in its save)
- Holds: the three save flags `ironman_unbroken`, `cheat_marked`, `switched_country`; campaign counters; the
  start facts tests read (start province count, start polity kind, started as subject, start macro-region).
- INV-ACH-13: once `ironman_unbroken` is false, or `cheat_marked` is true, it stays so for good.
- INV-ACH-14: no achievement unlocks while the campaign is not eligible.

### Entities and value objects

- **AchievementDefinition** (entity, id): `id`, `name`, `text`, `category`, `tier`, `hidden` (default false),
  `scope`, `moment`, `test`, optional `progress {stat, target}`, optional `full_game`, `refs`.
- **Tier** (value): copper | silver | gold | crown, with points 5 | 10 | 20 | 40. Launch counts: copper 38,
  silver 21, gold 10, crown 2. Meant for: copper = one action or a goal most players reach in their first
  campaign; silver = a goal you aim for; gold = a whole campaign shaped around it; crown = the hardest.
- **Moment** (value): `turn_end`, `year_end`, `harvest`, `spring_start`, `date` (checked once on that day),
  `battle_end`, `sea_battle_end`, `siege_end`, `war_end`, `rebellion_end`, `relation_changed`,
  `province_gained`, `invention_done`, `regiment_trained`, `lord_created`, `charter_granted`, `loan_closed`,
  `style_adopted`, `colony_founded`, `contact_made`, `fleet_home`, `food_policy_changed`, `event_choice`,
  `event_end`, `succession_plus_12_months`, `campaign_end`. `castle_gained` fires when a realm's castle is built or taken in a siege (D-ACH-1).
- **StoreIds** (value): Steam `ACH_` + id in capitals; Game Center bundle id + `.ach.` + id; Google Play id
  from the console, kept in `achievements.google.json`.
- **Icon** (value): 32 × 32 pixel art, 2-pixel tier-colour frame (copper, silver, gold, crown purple-gold),
  scaled × 2 (Steam 64) and × 16 (Game Center, Google Play 512) with nearest-neighbour; Steam locked variant
  in grey "unknown land" parchment tones.
- **EligibilityFlags** (value): `ironman_unbroken`, `cheat_marked`, `switched_country`.

### Domain services

- **AchievementEvaluator**: on a moment, runs only the rows whose `moment` names that moment, only for an eligible
  campaign, after the turn's own systems have run.
- **StoreReporter**: turns unlocks and progress into each store's call (incremental, percent, stat), keeps the
  best reported value, and drains the unlock queue.
- **StoreListBuilder** (build time): reads the YAML and writes Steam's VDF or web-form data, App Store
  Connect's list and Google's achievements CSV, with localised names and texts.

## 5. Requirements

### Purpose and fairness
- ACH-001 The achievements context shall give nothing inside the game for any achievement: no bonus, no unlocked nation and no cosmetic. [achievements §1]
- ACH-002 The achievements context shall keep one achievement list, identical on Steam, Game Center and Google Play Games. [achievements §1, §2]
- ACH-003 The achievements context shall use only achievements written for Pocket Hegemony's own systems, with no name, condition or icon taken from Europa Universalis IV or any other commercial game. [achievements intro]
- ACH-004 The achievements context shall phrase each test as a situation, not a country, using the event tree's `event_role` where a historical event is involved; only *One Island Realm* and *Lord of the River Bend* name a region. [achievements §4.1]
- ACH-005 The achievements context shall not tie any achievement to an event marked `narrative_only`, to conquering a named people, or to sacking or scorching land. [achievements §4.1]
- ACH-006 The achievements context shall make every test read a stat or a moment that an existing design defines, naming that section in `refs`; where the system is not designed yet the row shall carry a `gap-lists` reference. [achievements §4.1]
- ACH-007 The achievements context shall contain no luck-only goal; each goal can be planned for. [achievements §4.1]

### List limits, tiers and points
- ACH-008 The achievements context shall hold at most 100 achievements, ever. [achievements §2]
- ACH-009 The achievements context shall give each achievement the points of its tier: copper 5, silver 10, gold 20, crown 40, the same on Game Center and Google Play. [achievements §3; yaml tiers]
- ACH-010 The achievements context shall keep every achievement's points a multiple of 5 and at most 40, and the total at most 1,000. [achievements §2]
- ACH-011 The achievements context shall ship 71 achievements worth 680 points at launch, keeping 29 slots and 320 points for updates. [achievements §2, §4]
- ACH-012 When an update adds achievements, the achievements context shall keep at least 10 slots and 100 points in reserve afterwards. [achievements §9]
- ACH-013 The achievements context shall keep every name at most 24 characters and every text at most 100 characters. [achievements §4.1; yaml fields]
- ACH-014 Where a score or victory is added to the game, the achievements context shall give it its own achievements from the reserve. [achievements §10]

### Scope
- ACH-027 Where an achievement has `scope: campaign`, the achievements context shall require the whole condition to be met inside one game. [achievements §4.2]
- ACH-028 Where an achievement has `scope: lifetime`, the achievements context shall add its counter up across games in the player profile and mirror it to the store's progress where the store has one. [achievements §4.2]

### Hidden achievements
- ACH-029 The achievements context shall have no hidden achievement at launch, keeping `hidden: true` for later event chains whose existence is itself the surprise. [achievements §4.4]
- ACH-030 While a hidden achievement is not earned, the achievements context shall show it as "Hidden achievement" with its tier, keeping its name and text secret. [achievements §4.4; yaml fields]

### When tests run
- ACH-031 When a moment occurs, the achievements context shall run only the tests of rows whose `moment` names that moment. [achievements §5.1]
- ACH-032 Where a row's moment is `date`, the achievements context shall check it once, on that day. [achievements §5.1]
- ACH-033 The achievements context shall run its tests after the turn's own systems, at the very end of the turn order, so tests read final values. [achievements §5.1, §10]

### Which games count
- ACH-034 The achievements context shall let a campaign earn achievements only while it started as ironman and never left it, no cheat has been used, and the player still plays the realm they started with. [achievements §5.2, §11]
- ACH-035 If a campaign is not ironman, then the achievements context shall award no achievement in that campaign, for good. [achievements §5.2]
- ACH-036 If a debug, editor or "free play" cheat is used even once, then the achievements context shall treat the save as marked for good and award nothing from it, in-game or on any store. [achievements §5.2, §11]
- ACH-037 When the player switches to another country after game over, the achievements context shall stop awarding achievements from that moment. [achievements §5.2, §11]
- ACH-038 The achievements context shall let an ironman campaign earn achievements at any difficulty, with historical or free events. [achievements §5.2]
- ACH-039 The achievements context shall award no achievement in the tutorial. [achievements §5.2; tutorial §12]
- ACH-040 The achievements context shall read three flags on the save: `ironman_unbroken`, `cheat_marked` and `switched_country`. [achievements §5.2]
- ACH-041 The achievements context shall count a campaign towards lifetime counters only if it passes all three flags. [achievements §5.2]
- ACH-042 The achievements context shall show on the pause menu and on the new game screen whether the campaign can earn achievements. [achievements §5.2]
- ACH-043 When the player is about to take an action that would end a campaign's eligibility (turning on a cheat, switching country after game over), the achievements context shall warn once before it. [achievements §5.2]

### Progress bars
- ACH-044 Where a row has `progress`, the achievements context shall keep its game counter and report it to each store against its target. [achievements §5.3]
- ACH-045 Where the store is Google Play, the achievements context shall report progress as an incremental achievement, reporting targets larger than 10,000 in steps (people in tens of thousands, gold in tens). [achievements §5.3]
- ACH-046 Where the store is Game Center, the achievements context shall report progress as percent complete. [achievements §5.3]
- ACH-047 Where the store is Steam, the achievements context shall report progress as a stat bound to the achievement, with a progress popup at 25, 50 and 75 percent. [achievements §5.3]
- ACH-048 The achievements context shall reset campaign counters with each new game. [achievements §5.3]
- ACH-049 The achievements context shall report campaign progress to a store only when it beats the best value already reported to that store. [achievements §5.3]
- ACH-050 The achievements context shall show this campaign's own counter value in the in-game list. [achievements §5.3]

### Offline and failed calls
- ACH-051 When an achievement unlocks, the achievements context shall write it to the profile at once and show it in-game at once, whether or not a store is reachable. [achievements §5.4]
- ACH-052 While an unlock has not reached a store, the achievements context shall keep it in a queue and send it whenever the store is reachable, retrying at start-up and every few minutes. [achievements §5.4]
- ACH-053 When the game starts, the achievements context shall read the store's list and send anything the store is missing, so a new phone or a reinstall catches up. [achievements §5.4]

### Free tier and Steam demo
- ACH-054 Where the game is the iOS or Android free download, the achievements context shall award achievements as in the full game and keep them when the player buys. [achievements §5.5]
- ACH-055 Where a row is marked `full_game`, the achievements context shall not let it be earned with the free tier's countries alone (launch: *Our Own Banner*, *The Walls Held*, *The Four Quarters Hold*, *From One Hall*, *Many Tents, One People*, *Many Crowns*, *Crowns of the World*; D-ACH-3). [achievements §5.5; yaml]
- ACH-056 Because neither free country (Ottomans, France) has a single-province start, the achievements context shall mark *From One Hall* `full_game` (D-ACH-3). [achievements §5.5, §10]
- ACH-057 Where the game is the Steam demo, the achievements context shall award nothing to Steam directly and keep a local list from the demo's ironman games. [achievements §5.2, §5.5]
- ACH-058 When a demo player buys the full game, the achievements context shall read the demo's profile and award what was earned there. [achievements §5.5]

### Store ids and upload
- ACH-059 The achievements context shall never rename an `id` after release, and derive every store id from it. [achievements §6]
- ACH-060 The achievements context shall use `ACH_` + the id in capitals as the Steam id. [achievements §6]
- ACH-061 The achievements context shall use the bundle id + `.ach.` + the id as the Game Center id. [achievements §6]
- ACH-062 The achievements context shall keep the console-generated Google Play ids in a mapping file `achievements.google.json` after upload. [achievements §6]
- ACH-063 The achievements context shall generate each store's upload file (Steam's VDF or web form, App Store Connect's list, Google's achievements CSV) from the YAML with a build step, including localised names and texts. [achievements §6]
- ACH-064 When an achievement is retired, the achievements context shall hide it in every store and turn its test off, never deleting it, so players keep what they earned. [achievements §6]

### Icons
- ACH-065 The achievements context shall draw one icon per achievement at 32 × 32 in the game's pixel-art palette, with a 2-pixel frame in the tier's colour (copper, silver, gold, crown purple-gold). [achievements §7]
- ACH-066 The achievements context shall scale icons with nearest-neighbour and no smoothing: × 2 for Steam (64), × 16 for Game Center and Google Play (512). [achievements §7]
- ACH-067 The achievements context shall supply a Steam locked image in the grey "unknown land" parchment tones used for fog on the map; Game Center and Google draw their own locked state. [achievements §7]
- ACH-068 The achievements context shall make each icon show the thing the achievement is about, never a real flag or coat of arms. [achievements §7]

### In the game
- ACH-069 When an achievement unlocks, the achievements context shall show a toast that slides in at the top for three seconds with icon, name and tier, with a short chip-tune sting. [achievements §8]
- ACH-070 While a battle or event screen is open, the achievements context shall hold the toast until the screen closes. [achievements §8]
- ACH-071 Where the "Achievement toasts" setting is off, the achievements context shall show no toast and still unlock the achievement. [achievements §8; settings]
- ACH-072 The achievements context shall offer an achievements screen, reached from the main menu's More (D-ACH-13), as a grid of icons grouped by category; selecting one shows its text, progress and the date earned. [achievements §8]
- ACH-073 The achievements screen shall offer an "earnable in this campaign" filter that shows achievements not yet earned and not already ruled out (such as a date that has passed). [achievements §8]
- ACH-074 When an achievement unlocks, the achievements context shall add one line to that turn's report, with a jump to where it happened when there is a place (the castle, the battlefield). [achievements §8]

### Adding more later
- ACH-075 Where spare points are given to new achievements, the achievements context should give them mostly to new copper and silver goals. [achievements §9]

## 8. Policies (reactions to other contexts)

- When time-and-turns finishes the turn's own systems (`turn_end`, `year_end`, `harvest`, `spring_start`,
  `date`), then evaluate the rows for those moments.
- When warfare reports `battle_end`, `siege_end`, `war_end`, `style_adopted`, then evaluate those rows.
- When naval reports `sea_battle_end` or a fleet returns home (`fleet_home`), then evaluate those rows.
- When exploration reports `contact_made` or `colony_founded`, then evaluate those rows.
- When diplomacy or subjects report `relation_changed`, then evaluate those rows.
- When province or warfare report `province_gained` (and `castle_gained`, D-ACH-1), then evaluate those rows.
- When research reports `invention_done`, when recruiting reports `regiment_trained`, when realm reports
  `lord_created`, `charter_granted`, `loan_closed`, `food_policy_changed`, `succession_plus_12_months`, when
  rebellions report `rebellion_end`, when events report `event_choice` or `event_end`, then evaluate those rows.
- When the campaign reaches its end date (`campaign_end`), then evaluate *The Long Road*.
- When saves marks a save as left-ironman or cheat-marked, or game-shell reports a country switch after game
  over, then stop awarding for that campaign.
- When saves reports a profile restored on a new device, then run SyncWithStores.

## 9. Monthly turn

1. Read: the final values of every stat the month's tests read (all other contexts have run).
2. Run the `turn_end` rows; on January also `year_end`; on the harvest month `harvest`; on the first spring
   month `spring_start`; on a named date the `date` rows (once).
3. Moments raised during the turn (battles, sieges, events, inventions…) are tested after the turn's own
   systems too (§5.1: "Tests run after the turn's own systems").
4. Write unlocks to the profile; queue store calls; add turn report lines; queue toasts.
Dependency: last in the global order (gap list 1, item 20; time-and-turns).

## 13. Decisions and open questions

- **D-ACH-1** (was OQ-ACH-1) `castle_gained`: added to the moment list; it fires when a realm's castle is built or a castle is taken in a siege. A moment is cheaper than a compound test.
- **D-ACH-2** (was OQ-ACH-2) The YAML comment is stale: the tutorial earns no achievement, First steps included. The design and the tutorial design agree.
- **D-ACH-3** (was OQ-ACH-3) Free tier: the free countries are the Ottomans and France, so *From One Hall*, *Our Own Banner*, *Many Tents, One People*, *The Walls Held* and *The Four Quarters Hold* are marked `full_game`; every other row stays earnable with the free countries. Marking is simpler than changing the rows.
- **D-ACH-4** (was OQ-ACH-4) Save flags: X-16 decides it. The header carries `ironman_unbroken`, `cheat_marked`, `switched_country` and `began_as_tutorial`; lifetime counters and the demo's local list live in the player profile.
- **D-ACH-5** (was OQ-ACH-5) The six rows read the later designs: `started_as_subject` and `subject_of_anyone` from subjects; `tributaries_min: 5` counts subjects of the tributary kind (X-8); `contact_by: sea` is a first contact made by a fleet or an exploration ship; `founded_with_consent_of_local_people` is a colony founded by agreement (exploration); `fleet_crossed_ocean_and_returned` and `fleet_circumnavigated` read the voyage record of naval and exploration; macro-regions are the event tree's 13. The tests stay; only their sources are named.
- **D-ACH-6** (was OQ-ACH-6) The config key `on` is renamed `moment`. A plain name avoids the YAML trap.
- **D-ACH-7** (was OQ-ACH-7) Google Play steps: only targets above 10,000 are reported in steps, so *Counting House* (exactly 10,000) reports gold as is. The rule says "larger than".
- OQ-ACH-8 (release task) Store figures (Google points and counts, Steam's check) are checked again in each console before upload; the rules adopt the strictest.
- OQ-ACH-9 (release task) The names *The Walls Held* and *The Four Quarters Hold* need the sensitive-content review.
- OQ-ACH-10 (release task) The list is compared once against EU4's published list before release. The store retry interval is 5 minutes (provisional) and the toast uses audio's achievement stinger.
- **D-ACH-11** (was OQ-ACH-11) *Unconquered*: the macro-regions are the event tree's 13, with the Middle East counted as Asia; "outside" means a realm whose capital lies in another macro-region. It reuses existing regions.
- **D-ACH-12** (was OQ-ACH-12) The tutorial's last card says that achievements start in a real campaign; onboarding adds the line. One line of copy, no rule.
- **D-ACH-13** (was OQ-ACH-13) The achievements screen opens from the main menu's More, as screen flow places it (the latest design); the game menu does not list it. Latest decision wins.
- **D-ACH-14** (was OQ-ACH-14) Victory: X-12 decides how a campaign is won; no new achievement is added, and *The Long Road* still needs only reaching 31 August 1939. No new rows beyond the list.
